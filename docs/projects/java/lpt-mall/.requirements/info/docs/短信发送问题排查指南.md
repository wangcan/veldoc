# 短信发送问题排查指南

## 问题现象
发送注销账号短信时提示成功，但实际未收到短信。

## 数据库排查

### 查询短信发送日志

```sql
-- 查询最近的短信发送记录
SELECT id, mobile, send_status, send_time, api_send_code, api_send_msg,
       api_request_id, api_serial_no, template_code, template_content,
       channel_id, channel_code, create_time
FROM system_sms_log
WHERE mobile = '手机号'
ORDER BY create_time DESC
LIMIT 10;
```

**字段说明**:
- `send_status`: 发送状态
  - 0: 初始化（准备发送）
  - 10: 忽略发送（模板或渠道被禁用）
  - 20: 发送成功
  - 30: 发送失败
- `api_send_code`: 短信服务商返回的错误码
- `api_send_msg`: 短信服务商返回的错误消息
- `receive_status`: 接收状态（0=等待接收，20=接收成功，30=接收失败）

## 常见问题排查

### 问题1: 提示成功但未收到短信

**排查步骤**:
1. 查看日志中是否有 `[sendSingleSms][短信未发送！原因：模板或渠道被禁用]`
2. 如果有，检查短信模板和渠道配置：
   ```sql
   -- 查询短信模板配置
   SELECT id, name, code, status, channel_id
   FROM system_sms_template
   WHERE code = 'user-delete';

   -- 查询短信渠道配置
   SELECT id, code, status, signature
   FROM system_sms_channel
   WHERE id = (SELECT channel_id FROM system_sms_template WHERE code = 'user-delete');
   ```
3. 检查 status 字段：0=启用，1=禁用

---

### 问题2: 短信服务商返回错误

**排查步骤**:
1. 查看日志中的 `apiCode` 和 `apiMsg`
2. 查询数据库中的 `api_send_code` 和 `api_send_msg`
3. 根据错误码查询短信服务商的文档

---

### 问题3: MQ消息未消费

**排查步骤**:
1. 检查 RocketMQ 是否正常运行
2. 查看日志中是否有 `[onMessage]` 相关日志
3. 检查消费者组配置是否正确

---

## 短信配置检查

### 1. 检查短信模板配置

```sql
-- 注销账号的短信模板应该是场景5
SELECT * FROM system_sms_template WHERE code = 'user-delete';
```

**必要字段**:
- `code`: 必须是 `user-delete`
- `status`: 必须是 `0`（启用）
- `content`: 内容必须包含 `${code}` 参数
- `api_template_id`: 短信服务商的模板ID

### 2. 检查短信渠道配置

```sql
-- 查询短信渠道
SELECT * FROM system_sms_channel WHERE status = 0;
```

**必要字段**:
- `status`: 必须是 `0`（启用）
- `code`: 短信渠道编码（如：aliyun, tencent等）
- `api_key`, `api_secret`: 短信服务商的密钥配置

## 总结

通过以上日志追踪，可以清晰地看到短信发送的完整流程：

1. **请求进入** → 场景校验
2. **验证码生成** → 模板解析
3. **模板/渠道校验** → 关键检查点
4. **日志创建** → 状态记录
5. **MQ消息发送** → 异步处理
6. **消息消费** → 实际发送
7. **服务商响应** → 最终结果

重点关注的日志：
- `[sendSingleSms][短信未发送！原因：模板或渠道被禁用]` → 配置问题
- `[doSendSms][短信客户端调用完成]` 中的 `success` 字段 → 服务商响应
- 数据库 `system_sms_log` 表中的 `send_status` 和 `api_send_msg`
