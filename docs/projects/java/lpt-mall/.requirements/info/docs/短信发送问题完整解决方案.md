# 短信发送问题完整解决方案

## 问题背景

**用户反馈：** 发送注销账号短信时提示成功，但实际未收到短信。

**根本原因：**
1. 短信模板配置被 Redis 缓存
2. 直接在数据库修改配置后，缓存未更新
3. 应用读取的是缓存中的旧配置

## 快速解决步骤

### 步骤 1：清除 Redis 缓存

#### 方法 A：使用脚本（推荐）

```bash
cd /data/java/backend/ruoyi-vue-pro/scripts
./clear_sms_cache.sh
```

#### 方法 B：手动执行 Redis 命令

```bash
# 连接 Redis
redis-cli

# 删除 user-delete 模板的缓存
del sms_template:user-delete

# 验证删除
exists sms_template:user-delete
# 返回 0 表示已删除
```

### 步骤 2：验证数据库配置

```sql
-- 查询模板配置
SELECT id, code, channel_code, status, api_template_id
FROM system_sms_template
WHERE code = 'user-delete';

-- 查询渠道配置
SELECT id, code, status
FROM system_sms_channel
WHERE id = (SELECT channel_id FROM system_sms_template WHERE code = 'user-delete');
```

**检查要点：**
- `channel_code` 是否为期望的值
- `status` 是否为 0（启用）
- 渠道状态是否为 0（启用）

## 诊断流程

### 1. 检查日志关键信息

#### 1.1 是否从数据库加载？

```
✓ 正常：
[getSmsTemplateByCodeFromCache][从数据库查询短信模板 code:user-delete]

✗ 异常（缓存命中）：
直接显示 [validateSmsTemplate][短信模板获取成功（可能来自缓存）]
没有 "从数据库查询" 日志
```

#### 1.2 模板配置是否正确？

```
[validateSmsTemplate][短信模板获取成功（可能来自缓存）
  templateCode:user-delete
  id:xxx
  channelId:xxx
  channelCode:期望的值 ✓
  status:0 ✓
  apiTemplateId:xxx
  content:xxx
]
```

#### 1.3 是否发送成功？

```
✓ 成功：
[sendSingleSms][准备发送MQ消息 sendLogId:xxx ...]
[doSendSms][短信客户端调用完成 success:true ...]

✗ 失败：
[sendSingleSms][短信未发送！原因：模板或渠道被禁用 ...]
或
[doSendSms][短信客户端调用完成 success:false apiCode:xxx apiMsg:xxx]
```

### 2. 检查数据库

```sql
-- 查询最近的发送日志
SELECT
    mobile,
    template_code,
    channel_code,
    send_status,
    api_send_code,
    api_send_msg,
    send_time
FROM system_sms_log
WHERE template_code = 'user-delete'
ORDER BY create_time DESC
LIMIT 5;
```

**字段解读：**
- `channel_code` - 实际使用的渠道编码（应该是新值）
- `send_status`:
  - 0 = 初始化
  - 10 = 忽略发送（模板或渠道禁用）
  - 20 = 发送成功
  - 30 = 发送失败
- `api_send_code`, `api_send_msg` - 短信服务商返回的错误信息

### 3. 检查 Redis 缓存

```bash
redis-cli

# 查看缓存是否存在
exists sms_template:user-delete
# 0 = 不存在（已清除）
# 1 = 存在

# 查看缓存内容（如果存在）
get sms_template:user-delete

# 查看所有短信模板缓存
keys sms_template:*
```

## 常见问题 FAQ

### Q1: 清除缓存后还是用的旧值？

**可能原因：**
1. 应用有多个实例，部分实例缓存未清除
2. 清除缓存后，其他请求又加载了旧数据
3. 清错了 Redis 实例

**解决方法：**
```bash
# 清除所有短信模板缓存
redis-cli --scan --pattern "sms_template:*" | xargs redis-cli del

# 重启所有应用实例
```

### Q2: 短信服务商返回错误怎么办？

**查看日志中的错误信息：**
```
[doSendSms][短信客户端调用完成 success:false apiCode:xxx apiMsg:xxx]
```

**常见错误：**
- `apiCode: "TEMPLATE_NOT_FOUND"` - 短信服务商的模板ID不存在
- `apiCode: "INSUFFICIENT_BALANCE"` - 余额不足
- `apiCode: "INVALID_MOBILE"` - 手机号格式错误

**解决方法：**
根据错误码查询短信服务商的文档。

### Q3: 如何判断问题已解决？

**成功标志：**
1. 日志显示从数据库加载模板
2. 日志中的 `channelCode` 是新值
3. `send_status` = 20（发送成功）
4. 手机收到短信

## 预防措施

### 1. 使用管理后台更新配置

**推荐做法：** 始终通过管理后台更新短信模板，这样会自动清除缓存。

**访问路径：**
系统管理 → 短信管理 → 短信模板 → 编辑 → 保存

### 2. 修改数据库后立即清除缓存

如果必须直接修改数据库，修改后立即执行：
```bash
redis-cli del sms_template:user-delete
```

### 3. 添加配置监控

可以定期运行诊断脚本，检查配置是否一致：
```bash
# 定时任务（可选）
0 2 * * * /path/to/sms_template_diagnosis.sh | mail -s "短信配置检查报告" admin@example.com
```

## 总结

**核心问题：** Redis 缓存导致配置更新不生效

**解决步骤：**
1. 清除 Redis 缓存（`del sms_template:user-delete`）
2. 验证数据库配置正确
3. 重启应用或发送测试
4. 查看日志确认配置生效

**预防措施：**
- 使用管理后台更新配置
- 修改数据库后立即清除缓存
- 定期检查配置一致性

**验证成功：**
- 日志显示 "从数据库查询短信模板"
- 日志中的配置是新值
- 短信发送成功，手机收到验证码
