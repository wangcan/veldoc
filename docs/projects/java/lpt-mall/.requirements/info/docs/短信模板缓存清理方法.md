# 短信模板缓存清理方法

## 问题现象

在数据库中直接修改了 `system_sms_template` 表的数据（如 `channel_code`），但发送短信时仍然使用旧值。

## 原因分析

短信模板使用了 **Redis 缓存**，缓存的 key 格式为：
```
sms_template:{code}
```

当直接在数据库修改模板数据时，Redis 缓存不会自动更新，导致程序读取的是缓存中的旧数据。

## 解决方案

### 方案一：清除 Redis 缓存（推荐）

#### 方法1：使用 Redis 命令行

```bash
# 连接 Redis
redis-cli

# 查看所有短信模板缓存
keys sms_template:*

# 查看指定模板的缓存
get sms_template:user-delete

# 删除所有短信模板缓存
del sms_template:user-delete

# 或删除所有短信模板缓存（批量）
redis-cli --scan --pattern "sms_template:*" | xargs redis-cli del
```

#### 方法2：使用 Redis 管理工具

如果你使用 Redis 管理工具（如 RedisDesktopManager、Another Redis Desktop Manager 等）：

1. 连接到 Redis 服务器
2. 搜索 key：`sms_template:user-delete`
3. 删除该 key
4. 重试发送短信

#### 方法3：使用应用内置接口（如果有管理后台）

通过管理后台更新短信模板，会自动清除缓存：
- 访问：系统管理 → 短信管理 → 短信模板
- 编辑 `user-delete` 模板
- 点击保存（即使没有修改，保存也会触发缓存清除）

---

### 方案二：重启应用（简单粗暴）

重启应用后，缓存会自动失效。

```bash
# 如果是 Spring Boot 应用
# 停止应用
kill -15 <pid>

# 或者使用 systemd
systemctl restart yudao-server

# 或者使用 Docker
docker restart <container_name>
```

---

### 方案三：临时禁用缓存（测试环境）

如果需要频繁测试，可以临时禁用缓存（仅限测试环境）：

在 `application.yaml` 中添加：
```yaml
spring:
  cache:
    type: none  # 禁用所有缓存
```

**注意：** 生产环境不建议禁用缓存，会影响性能。

## 验证缓存是否清除

### 1. 查看 Redis 中的缓存

```bash
redis-cli

# 查看缓存是否存在
exists sms_template:user-delete
# 返回 0 表示不存在，1 表示存在

# 查看缓存内容
get sms_template:user-delete
```

### 2. 查看应用日志

清除缓存后，再次发送短信，查看日志：

```
[getSmsTemplateByCodeFromCache][从数据库查询短信模板 code:user-delete]
[getSmsTemplateByCodeFromCache][查询结果 code:user-delete id:xxx channelId:xxx channelCode:新的值 ...]
```

如果看到 "从数据库查询短信模板" 日志，说明缓存已清除，从数据库重新加载了。

```sql
-- 查询 user-delete 模板的当前配置
SELECT

    t.code AS template_code,
    t.channel_code AS template_channel_code,
    c.id AS channel_id,
    c.code AS channel_code,
    c.status AS channel_status,
    c.signature

WHERE t.code = 'user-delete';
```

## 常见问题

### Q1: 清除缓存后还是用的旧值？

**可能原因：**
1. 有多个 Redis 实例，清错了
2. 应用有多个实例，部分实例缓存未清除
3. 清除后又被其他请求加载了旧数据

**解决方法：**
```bash
# 清除所有短信模板缓存
redis-cli --scan --pattern "sms_template:*" | xargs redis-cli del

# 重启所有应用实例
```

### Q2: 如何判断是从缓存读取还是数据库读取？

**查看日志：**

- 如果日志显示：`[getSmsTemplateByCodeFromCache][从数据库查询短信模板 code:user-delete]`  
  → 说明缓存未命中，从数据库加载

- 如果日志显示：`[validateSmsTemplate][短信模板获取成功（可能来自缓存）...]`  
  但没有显示 "从数据库查询"  
  → 说明缓存命中

### Q3: 如何避免这个问题？

**最佳实践：**
1. 始终通过管理后台更新配置
2. 修改数据库后，立即清除缓存
3. 在测试环境验证后再上生产

## 缓存策略说明

### Spring Cache 注解

```java
@Cacheable(cacheNames = RedisKeyConstants.SMS_TEMPLATE, key = "#code")
public SmsTemplateDO getSmsTemplateByCodeFromCache(String code) {
    return smsTemplateMapper.selectByCode(code);
}
```

**说明：**
- `@Cacheable`：先查缓存，缓存没有则查数据库并缓存结果
- `key = "#code"`：缓存 key 为 `sms_template:{code}`
- 缓存时间：默认永不过期（除非手动清除或重启）

### 更新时清除缓存

```java
@CacheEvict(cacheNames = RedisKeyConstants.SMS_TEMPLATE, allEntries = true)
public void updateSmsTemplate(SmsTemplateSaveReqVO updateReqVO) {
    // 更新数据库
    // 方法执行后会自动清除所有短信模板缓存
}
```

**说明：**
- `@CacheEvict`：方法执行后清除缓存
- `allEntries = true`：清除该 cacheNames 下的所有缓存

## 总结

**核心问题：** 直接修改数据库不会触发缓存清除

**解决方法：**
1. **快速解决：** 清除 Redis 缓存 `del sms_template:user-delete`
2. **彻底解决：** 重启应用
3. **预防措施：** 使用管理后台更新配置

**验证方法：**
1. 查看 Redis 缓存是否清除
2. 查看应用日志中的模板信息
3. 测试发送短信验证新的配置是否生效
