## 1. 产品概述

### 1.1 业务背景

公司经营**定制字帖**业务：用户下单后提供自己的姓名、性别并选择版式，平台为其生成对应的**姓名字帖 PDF 文件**，供打印装订成册后发货。男生、女生可选用**不同的封面和内容页纸张**，因此同一版式按性别区分商品编码。

订单处理由后台运营人员在管理系统中登记，系统负责字帖内容的展开、单页 PDF 的生成与整本合并，运营人员在列表中跟踪生成进度与异常，最终取用生成的整本 PDF 进行打印。

### 1.2 产品目标

1. 运营人员能按批次高效登记姓名字帖需求（单个多音字姓名 / 批量普通姓名）；
2. 系统自动完成"姓名 → 单页拆解 → 单页 PDF → 整本 PDF"的生成流水线，无需人工排版；
3. 相同单页跨记录复用，避免重复生成，缩短批量处理时长；
4. 异常（姓名不合规、缺字库、生成失败）可被自动识别、明确提示并单独归类，运营人员可针对性处理；
5. 提供版本/版式的配置化管理，业务调整无需发版。

### 1.3 产品形态

纯后端 API 服务（`/api/v1/*`），配套独立的前端管理界面（不属于本模块范围）。另提供 5 个运维命令用于配置数据同步与 PDF 生成调度。

## 2. 用户角色与权限

### 2.1 系统用户

| 角色 | 说明 |
| --- | --- |
| 超级管理员/系统管理员 | 管理管理员账号、角色权限（系统管理权限） |
| 运营人员 | 登记姓名字帖、跟踪生成进度、处理异常（姓名字帖权限） |
| 字库维护人员 | 维护字库文件与字库数据（字库管理权限） |

系统内置**极简版角色权限模型**：每个管理员分配**单一角色**（或不分配），每个角色勾选若干**权限选项**（菜单级权限，非接口级鉴权）。权限选项词汇表：

| 权限标识 | 名称 |
| --- | --- |
| index | 首页 |
| namecopybook | 姓名字帖 |
| childrenstamp | 儿童印章 |
| nametag | 姓名贴 |
| fontmanage | 字库管理 |
| system | 系统管理 |

### 2.2 鉴权规则

- 所有接口（除登录）须携带有效 JWT；
- 被禁用的账号不能登录，已发放 token 的有效性随刷新校验；
- 姓名字帖登记的操作者须可追溯（生成日志记录操作者 ID 与账号快照）。

## 3. 术语定义

| 术语 | 定义 |
| --- | --- |
| 版本（version） | 字帖的产品版本（如 ncv_1），决定整体风格，男女各有一张预览图 |
| 版式（layout） | 版本下的具体规格组合：内容页数 × 字体（手写体/楷体）× 是否带笔顺；每个版式有男女各自的商品编码 |
| 字体（font） | handwritten 手写体 / standard 楷体（标准体） |
| 笔顺（has_stroke_order） | 单页是否展示汉字笔画顺序，0 无 / 1 有 |
| 批次码（batch_code） | 一次登记/一批订单的业务分组标识，批内记录有连续序号（1,2,3…） |
| 多音字编码（polyphonic_code） | 多音字姓名的读音选择，按姓名位置以下划线拼接（如 `2_4` = 第 1 字取第 2 读音、第 2 字取第 4 读音）；空串表示非多音字 |
| 单字页 | 内容为姓名中单个汉字的 pdf 页（如"姓"字练习页） |
| 组合页 | 内容为姓名多个字组合的 pdf 页（部分组合/全名/全名拓展） |
| 单页代码（page_code) | 基础单页的类型标识：first/second/third/fourth（单字）、part1/part2（部分组合）、full（全名）、fullext（全名拓展） |
| 字数配置代码 | 三维标识拼接 `{页数}_{姓名字数}_{规则代码}`（如 p32_two_standard），描述某版式下某字数姓名的单页拼装规则 |
| 登记记录 | 一条姓名字帖生成任务（批次+姓名+性别+多音字编码+版式 唯一） |
| 重新登记 | 对已存在登记记录的重复提交：不新增记录，只追加日志并刷新最后登记时间 |
| 生成日志 | 每次登记/重新登记的操作留痕（操作者、时间） |

## 4. 功能需求

### 4.1 管理员认证与账号（FR-A）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-A1 | 管理员使用账号+密码登录，获取访问令牌（JWT，含有效期） | 账密错误提示"账号或密码错误"；被禁用账号不能登录 |
| FR-A2 | 登录后可查看自己的信息（含所属角色） | 返回账号、头像、昵称、手机号、状态及角色信息 |
| FR-A3 | 管理员可编辑自己的资料：头像、昵称、手机号、密码 | 不能自行修改账号、状态、角色等管理字段；密码留空则不修改 |

| FR-A5 | 姓名字帖记录须可追溯登记操作者 | 生成日志含操作者 ID 与账号快照，管理员删除不影响历史日志 |

### 4.4 字库管理（FR-D）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-D1 | 字库表以**单字**为粒度，标记：有无标准体字库、有无手写体字库、两种字体是否已使用 | — |
| FR-D2 | 字库分页列表，支持按单字（模糊）与 6 个布尔维度筛选：有标准体/有手写体/两者都有/标准体已用/手写体已用/两者都已用 | 筛选参数仅在传值时生效 |
| FR-D3 | 字库详情：返回单字基础信息及**字体文件内容**（base64 编码字节流） | 无对应字体文件或标记为假时该字段为 null；字库不存在返回 404 |
| FR-D4 | 提供字库扫描同步命令：扫描标准体/手写体字库目录（文件名去扩展名 = 汉字），新增缺失单字并置位存在标记 | 同步**不重置**已有标记；两目录均未配置时报错 |
| FR-D5 | 登记姓名时，字库表中不存在的单字自动补录（存在标记全为否） | 补录后走缺字库校验，标记为无字库异常 |

### 4.5 版本与版式管理（FR-E）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-E1 | 版本为只读基础数据（代码、名称、男女预览图、排序、状态），**不提供**任何维护接口 | 维护途径：迁移/命令/直接操作数据库 |
| FR-E2 | 版式归属于版本，由"内容页数 × 字体（手写体/楷体）× 是否带笔顺"确定；每版式含男女商品编码、排序、备注、状态（使用中/停用/已弃用） | 匹配键含笔顺：同页数不同笔顺是不同版式 |
| FR-E3 | 版式数据由配置文件 + 同步命令维护，**不提供** CRUD 接口 | 配置项按字体自动生成两条版式（先手写体后楷体） |
| FR-E4 | 版式名称按规则自动生成：`{页数}页{有|无}笔顺{手写体|楷体}` | 如"36页有笔顺手写体" |
| FR-E5 | 版式同步命令只更新名称/笔顺/商品编码/备注，**不改动**已有版式的状态；排序仅对新版式赋值（版本内从 1 递增） | 重跑命令不重排存量；引用不存在版本代码时报错 |
| FR-E6 | 版式携带三个字数配置代码字段（2/3/4 字姓名），由字数配置同步命令按页数批量维护 | 规则选择：优先 standard；无法确定时保持原值并提示 |
| FR-E7 | **接口1**（版本版式明细）：按性别（男/女）分组返回各版本及其版式（id/名称/状态字符串），版式过滤已弃用、按排序返回 | 男女各取自己的版本预览图 |
| FR-E8 | **接口2**（版本版式列表）：按版本分组，男女两节各带预览图，版式附带 demo 演示文件列表 | demo 按版本+版式+性别配置，未配置返回空数组 |
| FR-E9 | 登记时所选版式须为**使用中**状态；已停用/已弃用版式拒绝登记并明确提示 | 停用与已弃用提示文案不同 |

### 4.6 姓名字帖登记（FR-F）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-F1 | 多音字姓名**单条**登记：批次码、性别、版式、单个姓名、多音字编码 | 五要素必填，中文报错 |
| FR-F2 | 普通姓名**批量**登记：批次码、性别、版式、姓名列表 | 列表去重后逐条处理；多音字编码固定为空 |
| FR-F3 | **重新登记**：与已有记录（批次码+姓名+性别+多音字编码+版式 五要素相同）重复提交时，不新增记录，追加生成日志并刷新最后登记时间，**沿用当前状态** | 不重复生成单页，不重置已有状态 |
| FR-F4 | 批次内序号自动分配为当前最大值 +1，同批次连续递增 | 并发登记不重号 |
| FR-F5 | 新记录创建时快照版式信息：版本代码、版式名称、按性别取的商品编码 | 版式后续变更不影响历史记录 |
| FR-F6 | 姓名合法性校验：仅允许中文（一-龥），中文字数 2~4 字 | 不合规标记"姓名字数异常"并给出原因（有字母/数字/特殊字符、少于两个字、超出4个字） |
| FR-F7 | 字库校验：姓名每个单字须有版式字体对应的字库文件 | 缺失标记"无字库异常"并给出缺字清单（如：缺少字：X、Y） |
| FR-F8 | 单页展开：按版式的字数配置代码解析分组规则，单页代码去重（保留首现顺序）后逐个生成单页记录与关联记录 | repeat 重复次数在关联层不展开（关联每单页代码一条）；展开顺序作为整本拼接顺序 |
| FR-F9 | 单页全局复用：单字页以 版本+字体+笔顺+汉字+字库+多音字编码 唯一，组合页以 版本+字体+笔顺+汉字+单页代码+多音字编码 唯一；**同版本同字体同笔顺的单页跨版式共享** | 相同单页只生成一次，被多条记录引用 |
| FR-F10 | 多音字编码传递规则：单字页取编码按姓名位置拆分后的对应段（如 `2_4` → 首字页用 `2`、第二字页用 `4`）；组合页用完整编码 | 超出位置范围为空段 |
| FR-F11 | 单页初始状态为"未生成"；关联记录状态与单页保持同步 | — |
| FR-F12 | 校验与展开全部通过后记录进入"处理中"并清空异常描述；任一环节异常则记录停在该异常状态（**不生成任何单页/关联**） | 配置类异常（代码不存在、引用未定义单页、内容取不到）归入"其他异常" |
| FR-F13 | 登记响应返回本次处理结果汇总：处理总数、去重数、新增数、进行中数、已完成数、异常数，并提示新增与重新登记条数 | total 按未去重条数计 |

### 4.9 整本 PDF 生成（FR-I）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-I1 | 提供整本生成命令：处理"处理中"记录，以及"已完成但标记需要重新生成"的记录 | 重新生成触发条件 need_regenerate=1 |
| FR-I2 | 前置条件：记录的全部关联单页均"已完成"，否则本轮跳过（不算失败，等下一轮） | — |
| FR-I3 | 文件完整性校验：任一关联单页的 pdf 文件缺失 → 单页、关联（全局同步）、记录三处标记"生成pdf异常" | 异常描述统一为"生成pdf异常" |
| FR-I4 | 拼接顺序：重新按版式字数配置的分组顺序与 repeat 重复次数展开单页文件序列 | 配置与登记时不一致（代码不存在/引用未关联单页/未展开任何单页）→ 记录"其他异常" |
| FR-I5 | 合并输出：`{pdf根目录}/final/{批次码}_{批次内序号}_{姓名}.pdf`，重新生成时同名覆盖 | — |
| FR-I6 | 合并成功 → 记录"已完成"、清空异常描述、重置重新生成标记 | — |
| FR-I7 | 合并失败（如单页 pdf 损坏）→ 记录"其他异常"，描述前缀"整本pdf合并失败："（截断 500 字） | — |
| FR-I8 | 任一记录失败，命令整体返回失败状态 | — |

## 5. 状态体系

### 5.1 姓名字帖记录状态

| 状态 | 名称 | 进入条件 |
| --- | --- | --- |
| pending | 未处理 | 新记录创建的初始状态 |
| processing | 处理中 | 单页与关联全部生成成功（等待 PDF 生成） |
| completed | 已完成 | 整本 pdf 生成成功 |
| name_abnormal | 姓名字数异常 | 姓名含非中文字符 / 中文字数不在 2-4 |
| font_abnormal | 无字库异常 | 姓名单字缺少版式字体对应字库 |
| pdf_abnormal | 生成pdf异常 | 关联单页的 pdf 文件缺失 |
| other_abnormal | 其他异常 | 字数配置异常 / node 脚本失败 / 合并失败等 |

### 5.2 单页/关联状态

| 状态 | 名称 | 进入条件 |
| --- | --- | --- |
| （空串） | 未生成 | 单页创建的初始状态 |
| completed | 已完成 | node 脚本执行成功 |
| other_abnormal | 其他异常 | node 脚本执行失败/超时 |
| pdf_abnormal | 生成pdf异常 | 整本命令发现文件缺失 |

关联状态始终与所引用单页同步。列表归类：**正在进行中** = 未处理+处理中；**已完结** = 其余。

## 6. 核心业务流程

### 6.1 登记流程

```
运营人员提交（批次码/性别/版式/姓名[/多音字编码]）
  → 参数校验（版式须使用中）
  → 同批次加锁取号
  → 已存在相同记录？─ 是 → 追加日志 + 刷新最后登记时间（重新登记）
  │                    否 → 创建记录（未处理）+ 日志
  → 姓名/字数校验 →（异常 → 姓名字数异常，终止）
  → 拆字补录字库 → 字库校验 →（异常 → 无字库异常，终止）
  → 解析版式字数配置 →（异常 → 其他异常，终止）
  → 去重展开单页（全局复用 firstOrCreate）+ 建立关联
  → 记录 → 处理中
  → 返回状态汇总（总数/去重/新增/进行中/已完成/异常）
```

### 6.2 生成流水线（周期调度）

```
周期任务：
  ① generate-page-pdfs   未生成单页 → node 脚本渲染 → 单页 完成/其他异常（同步关联）
  ② generate-final-pdfs  处理中（或需重生成）记录
                          → 单页未全部完成 → 跳过
                          → 文件缺失 → 三处标记 pdf 异常
                          → 按配置展开并合并 → 记录 完成（重置重生成标记）
```

### 6.3 配置维护流程

```
业务调整（新版本/新页数/新字库文件）
  → 更新 version_layouts.php / name_page_configs.php / 字库目录
  → copybook:sync-version-layouts（建改版式）
  → copybook:sync-layout-char-configs（补字数配置代码）
  → copybook:sync-fonts（字库入库）
```

## 8. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 安全 | JWT 鉴权；密码哈希存储且不外露；禁用账号即时失去登录能力；操作留痕 |
| 一致性 | 登记与单页/关联生成在同一数据库事务；批内序号分配加锁防并发重号；单页状态与关联状态同步更新 |

## 9. 约束与边界

1. **姓名范围**：仅支持 2~4 个中文字符的姓名；多音字仅支持按位置指定的读音编码，暂不支持自动注音。
2. **版式约束**：登记只能选择"使用中"的版式；版式数据不提供界面维护，须由开发/运维通过命令维护。
3. **单页共享边界**：单页唯一键基于版本代码（不含版式 ID），同版本同字体同笔顺下不同版式的单页互相复用——调整脚本输出内容需评估对存量复用单页的影响。
4. **记录不可变**：登记记录无编辑/删除能力；错误的登记通过异常状态标记隔离，不做物理修正。
5. **重新登记边界**：重新登记不重置状态、不重新生成单页；需要重做的场景由"需要重新生成"标记驱动整本重合并（单页层强刷本期未启用）。
6. **PDF 技术约束**：合并引擎（FPDI 免费版）无法解析 PDF 1.5+ 压缩对象流格式，node 脚本输出须为兼容格式，否则合并失败归入"其他异常"。
7. **环境依赖**：单页生成依赖服务器可执行 node 及脚本目录、字库目录、pdf 输出目录三处路径配置。
